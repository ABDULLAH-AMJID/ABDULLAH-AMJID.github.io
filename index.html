PhoneCam Pro ↗

Systems / C++
Custom DirectShow driver · Windows kernel-adjacent

Turns an Android phone or iPhone into a real Windows webcam — one that Zoom, Teams, and Google Meet detect as physical hardware. No DroidCam, no OBS, no third-party drivers.

The core is a DirectShow filter written from scratch in C++ that registers itself as a system camera device and pulls frames from shared memory. A Python server receives the phone's camera stream over WiFi or USB tethering and writes into that shared buffer. Supports live quality switching from 480p to 1080p, remote front/back camera flip, and automatic reconnection on network drop.

SpaceMedic ↗

Desktop / Safety-critical
Offline Windows storage & memory analyser · MIT licensed

Answers two questions: what is using my disk and memory, and what can I safely reclaim. Built for developers whose machines quietly fill up with node_modules, virtual environments, build outputs, package caches, and AI model downloads.

Designed safety-first: read-only until the user explicitly selects something, deletions route through the Recycle Bin, and it will never touch Windows, System32, WinSxS, or pagefile.sys. Ships with 29 regression tests, an eight-language localisation framework, and a validated community rule system that rejects absolute paths and directory traversal. No telemetry, no account, no network calls.

PythonTkinter Windows APIRegression Testing i18nMIT

EarBridge NEXUS ↗

Real-time audio
Low-latency audio bridge over LAN

Most Bluetooth earbuds pair with only one device at a time. EarBridge streams laptop audio to your phone over WiFi, where a web app plays it through the earbuds already connected there — so you hear both devices at once, with no extra hardware.

Uses the A2DP music profile rather than the low-quality HFP call profile, and runs playback on an AudioWorklet so it survives OS thread suspension when the browser is backgrounded. Includes an adaptive jitter buffer that measures live network jitter and retunes buffer depth, RTT-based signal quality monitoring, and per-client isolated send queues so one slow device never stalls the others.

04

Research & Interests

My work keeps returning to one theme: making the operating system do something it wasn't designed to do, then wrapping it in an interface an ordinary person can use without fear. A virtual camera driver, an audio path between two devices that were never meant to share one, a cleanup tool that refuses to delete anything dangerous.

I am especially drawn to real-time systems — latency budgets, jitter, buffer management, and the trade-offs between throughput and responsiveness — and to safe systems design, where the hard problem is not making a feature work but guaranteeing it can never cause harm.

I am currently seeking internship opportunities in systems, tooling, or real-time media engineering, and exploring graduate study in operating systems and computer architecture.
